# «Лунный улов» — план разработки

Версия плана: 1.1 · 2026-11-01 (правки: GitHub с v0.0.x, ранняя финальная графика, музыка от агента, очеловечивание текстов, правило шейдеров) · Godot 4.7.x · Web (Яндекс Игры)
Статусы выполнения — в `docs/PROGRESS.md`, журнал — в `docs/DEVLOG.md`.

---

## 0. Видение

**Одной фразой:** уютная тёмная рыбалка — старый волшебник ловит странных существ в проклятых водах под луной, собирает бестиарий и узнаёт историю утонувшего замка.

**Столпы**
1. **Уютная тьма** — мрачно, но безопасно: туман, луна, руины, меланхолия. Без крови, жестокости, чёрной магии, религиозной символики.
2. **Сочность (juice)** — каждое действие отзывается анимацией, частицами, звуком, вибрацией.
3. **Коллекция и тайна** — бестиарий, фазы луны, редкие существа, лор.
4. **Одно касание** — играется одним пальцем, мышью, пробелом/Enter, пультом ТВ.

**Визуал:** стиль «B + свет A» — пиксель-арт 16 бит (концепт B), свет и атмосфера живописи 80-х (концепт A): светящаяся вода, туман, плёночное зерно, виньетка. Герой — волшебник в остроконечной шляпе. Вертикаль 9:16. Концепты: `docs/concept/` (01–02 — утверждённый стиль, 03–04 — референс света).

**Звук:** dark ambient (вайб oneheart) + dungeon synth (вайб hide cs01). Музыку и звуки пишет агент сам: синтез на Python → OGG (§2.8). Только оригинальный материал, без сэмплов чужих треков.

## 1. Зафиксированные технические решения

| Параметр | Решение |

| Движок | Godot 4.7.x, GDScript со статической типизацией |
| Рендерер | Compatibility (WebGL 2) — единственный вариант для Web |
| Экспорт | Web, без поддержки потоков (по умолчанию с 4.3): не нужна cross-origin isolation, совместимо с рекламой |
| Базовое разрешение | 360×640 (портрет). 1 px арта = 1 px вьюпорта. Stretch: viewport, aspect: expand. Scale mode (integer/fractional) — финально по визуальному тесту на Э3 |

| Шрифт | Пиксельный, кириллица + латиница (+ турецкие символы), лицензия OFL/CC0 |

| Языки | ru, en на старте; tr — после релиза |

| Музыка и SFX | Пишет агент: синтез на Python (numpy/scipy) → WAV → OGG через ffmpeg; партитуры-скрипты в `tools/audio/` |

| Тексты | ru — humanizer-ru, en — humanizer (§2.7, `docs/TEXT_GUIDE.md`) |

## 2. Архитектура и правила кода

### 2.1 Композиция, а не наследование
- Поведение собирается из **узлов-компонентов** (дочерние `Node`/`Node2D`/`Control` с `class_name`). Один компонент — одна ответственность, настройка через `@export`.
- Наследуемся **только от встроенных типов** Godot. Собственных иерархий (`BaseFish → RareFish`) нет.
- Компонент получает зависимости через `@export var target: Node2D` или `owner`, без `get_parent().get_parent()`.
- Связи: «сигналы вверх, вызовы вниз»; события между фичами — через автозагрузку `EventBus`.
- **Данные — в Resource (`.tres`):** `FishData`, `FishBehavior`, `LocationData`, `UpgradeData`, `BaitData`, `MoonEventData`, `LoreEntry`. Баланс правится в инспекторе.
- Состояния (рыбалка, UI-флоу) — компонент `StateMachine` с дочерними узлами-состояниями.

### 2.2 Всё — сценами и узлами
- Любой видимый объект, UI, эффект, звук — `.tscn`, собранная из узлов.
- **Запрещено:** строить деревья узлов в коде (`Node.new()`, `add_child(Sprite2D.new())`), рисовать объекты через `_draw()` вместо узлов.
- **Разрешено:** инстанцировать готовые сцены (`preload(...).instantiate()`) для рантайм-спавна (вспышки, всплывающие числа, монеты), менять свойства существующих узлов, твины.
- Авторские анимации — `AnimationPlayer` / `AnimatedSprite2D` в сцене; динамический «сок» — твин-компоненты.
- Шейдеры — `.gdshader` в `res://shaders/`, материалы — `.tres`.

### 2.4 Стиль кода
- Файлы и функции — `snake_case`, `class_name` и узлы — `PascalCase`.
- Статическая типизация везде, `@export_group`, `##`-комментарии для подсказок в инспекторе.
- Никаких «магических чисел» — `@export` или Resource.
- Ноль ошибок и предупреждений в консоли.

### 2.5 Арт-конвейер: финальная графика как можно раньше
Каждый графический элемент проходит один путь:
1. Агент генерирует временный вариант и доводит его в Computer: палитра, пиксельная сетка, размер, прозрачный фон. Кладёт в проект сразу под финальным именем и путём (`res://art/...`).
2. В том же чекпоинте агент пишет готовый промпт для ChatGPT в `docs/ART_PROMPTS.md` (ID, назначение, путь, размер в игре, фон, раскладка кадров) и показывает его пользователю.
3. Пользователь генерирует финал в ChatGPT и кладёт файл в Pod `incoming/art/<ID>.png`.
4. Агент обрабатывает финал тем же скриптом `tools/art/` и заменяет файл по тому же пути. Сцены не меняются: размеры и точки привязки совпадают.
5. Статус в реестре `docs/ART_PROMPTS.md`: `временный` → `промпт выдан` → `финал получен` → `в игре`.

Появился новый элемент по ходу работы — та же схема, без исключений.

### 2.6 Правило шейдеров: сначала картинка, потом код
Перед любым визуальным шейдером (вода, небо, туман, свечение, переходы, блики UI и т. д.):
1. Агент генерирует 1–3 кадра «как это выглядит в нашей игре» в утверждённом стиле.
2. Кадры кладутся в `docs/shader_refs/<shader_id>/` и показываются пользователю.
3. Только после этого пишется шейдер с этими кадрами как референсом. В шапке `.gdshader` — ссылка на кадры и на источник, если основа взята с godotshaders.com.
4. Результат сверяется с кадром по скриншоту из игры.

### 2.7 Тексты: очеловечивание обязательно
- Все русские тексты в игре проходят навык humanizer-ru, английские — humanizer. Копии правил: `docs/text/vendor/`.
- Тон персонажей, типографика, запреты — `docs/TEXT_GUIDE.md`; учёт пройденных текстов — `docs/text/TEXT_LOG.md`.
- Русский — исходный язык. Английский пишется заново по смыслу, затем проходит humanizer.

### 2.8 Музыка и звуки пишет агент
- Синтез в Computer на Python (numpy/scipy): пэды, дроны, FM-колокольчики, «касио»-лиды в духе dungeon synth, шум плёнки, реверберация. Рендер в WAV → OGG Vorbis через ffmpeg.
- Скрипты-партитуры лежат в `tools/audio/`: любой трек можно перегенерировать и поправить.
- Треки — бесшовные петли со слоями (основа, мелодия, напряжение), чтобы AudioDirector смешивал их по ситуации.
- Пробный трек и пробные SFX — уже на Э0.5, чтобы утвердить звучание до основной работы.

## 3. Планка качества «fancy & juicy» (чек-лист для каждой фичи)
- Каждое нажатие → анимация + звук (+ вибрация на телефоне, где доступна).
- Нелинейные изинги везде; UI появляется и исчезает анимированно (offset transform).
- Hit-stop 50–100 мс на подсечке и поимке; мягкая тряска камеры по модели «травмы».
- Squash & stretch: поплавок, кнопки, монеты, существо в прыжке.
- Частицы: брызги, капли, искры, светлячки, мотыльки у фонаря, монеты летят по дуге в счётчик.
- Счётчики прокручиваются, числа всплывают.
- Раскрытие редкости: лучи, свечение цвета редкости, блик-шейдер на карточке, штамп «Новое!».
- Живой фон в простое: шляпа и плащ на ветру, мерцание фонаря, окна замка, падающие звёзды, дрейф тумана.
- Переходы экранов — туманная шторка / растворение шейдером.
- 60 FPS на среднем Android; пресеты качества; опция «меньше вспышек и тряски».

## 4. Требования Яндекс Игр, встроенные в дизайн
- Первая поимка ≤ 30 с от старта (метрика «доля сессий длиннее 60 с»); стартовая загрузка — минимальная.
- `LoadingAPI.ready()` — когда меню готово к взаимодействию; `GameplayAPI.start()/stop()` по игровым состояниям.
- Пауза и выключение звука при потере фокуса и во время рекламы.
- Прогресс сохраняется сразу после значимого действия.
- Язык определяется автоматически; ручной выбор — иконка глобуса, языки подписаны на самих себе.
- Полноэкранная реклама — только в логических паузах (возврат на берег / после продажи) с кулдауном. Rewarded — только бонус: золотая наживка, ×2 к продаже, ускорение сетей.
- Контент: без крови, чёрной магии, религиозной символики, политики и войн; подходит для всех возрастов (иначе не попасть в подборки).
- Распакованный архив ≤ 100 МБ; имена файлов без пробелов и кириллицы.
- Десктоп: соотношение сторон не шире 2:1, поле растягивается до края.
- Интерактивный ИИ в игре запрещён; заранее сгенерированные ассеты разрешены.
- Хорошая практика (сверить с актуальным чек-листом на Э7.8): без контекстного меню, выделения текста и прокрутки страницы; клавиши — по физическим кодам (не зависят от раскладки).

## 7. Протокол сохранения прогресса (обязателен)

**Где что лежит (Pod «dark fantasy»):**
- `lunnyi_ulov/` — рабочая копия проекта (= корень Godot-проекта = корень репозитория).
- `builds/lunnyi_ulov_latest.zip` + `builds/lunnyi_ulov_vX.Y.Z.zip` — архивы проекта.
- `references/` — референсы пользователя (чужие работы, только для настроения, в репозиторий и игру не попадают).
- `incoming/art/` — финальная графика от пользователя из ChatGPT; `incoming/repo/` — zip репозитория, если пользователь менял проект сам.
- В проекте: `docs/PROGRESS.md`, `docs/DEVLOG.md`, `docs/DECISIONS.md`, `docs/ASSETS_LICENSES.md`.

**Начало сессии агента**
1. `START_HERE.md` → `lunnyi_ulov/AGENTS.md` → `docs/PROGRESS.md` (блок «Текущее состояние») → последние 3 записи `docs/DEVLOG.md`.
2. Если пользователь выгрузил новую версию (GitHub / zip) — сначала синхронизировать рабочую копию.
3. Продолжить с «Следующего шага».

**Чекпоинт** — после каждого подэтапа и внутри крупного подэтапа каждые ~3–5 изменённых файлов:
1. Записать файлы в рабочую копию.
2. Обновить `PROGRESS.md`: статус (`[ ]` → `[~]` → `[x]`), «Текущее состояние», «Следующий шаг» (конкретно, до файла/узла/функции).
3. Добавить запись в `DEVLOG.md` по шаблону.
4. Пересобрать архив: `lunnyi_ulov_latest.zip`; при закрытии подэтапа — ещё и версионный.
5. Сообщить пользователю: что сделано, как проверить, какой архив скачать, сообщение коммита (оно же в DEVLOG). Пользователь коммитит и пушит, либо агент сам, если к Dust подключён GitHub.

**Версии:** `v0.<этап>.<подэтап>` внутри этапа; `v0.<этап>.0` — веха.

## 8. Ограничения и как с ними работаем
- **Нет редактора Godot у агента.** В Computer нет Godot и интернета: агент пишет `.tscn/.tres/.gd/.gdshader` текстом, но не запускает игру и не делает веб-сборку. → Мелкие итерации; к каждому подэтапу — инструкция «как проверить» на 1–2 минуты; ошибки консоли пользователь присылает текстом или скриншотом.
- **Импорт.** Godot сам создаёт `.import` и `uid` при первом открытии — после этого их нужно закоммитить.
- **Шейдеры.** godotshaders.com — CC0 / MIT / GPL v3 (указано в посте): берём CC0 и MIT, GPL v3 не берём. Shadertoy по умолчанию — CC BY-NC-SA 3.0 (некоммерческая): в монетизируемой игре нельзя, используем как вдохновение и пишем своё, либо если автор явно дал другую лицензию. Всё — в `ASSETS_LICENSES.md`.
- **Арт.** Временные ассеты генерирует агент, финальные — пользователь в ChatGPT по промптам агента (§2.5); палитру и сетку доводят скрипты `tools/art/`. Покадровая анимация — самое сложное для генерации: раскадровки в промптах + шейдеры (ветер, дыхание) + твины; при необходимости ручная доводка в Aseprite/LibreSprite.
- **Музыка.** Пишет агент синтезом (§2.8). Живых инструментов и сэмплов нет, звучание строится на синтезе — это хорошо ложится на dark ambient и dungeon synth. Слушает и утверждает пользователь.
- **GitHub.** У агента пока нет GitHub-инструмента: агент обновляет рабочую копию и архив в Pod, пользователь коммитит по `docs/GITHUB.md`. Если подключить GitHub к Dust (администратор workspace), агент сможет работать с репозиторием напрямую.
