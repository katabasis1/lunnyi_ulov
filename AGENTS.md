# AGENTS.md — правила для любого агента, работающего над «Лунным уловом»

## 1. С чего начать (каждая сессия)
1. Прочитай `docs/PROGRESS.md`: «Текущее состояние» и «Следующий шаг».
2. Прочитай последние 3 записи `docs/DEVLOG.md`.
3. Контекст: `docs/PLAN.md` (этапы, архитектура, конвейеры), `docs/GDD.md` (дизайн), `docs/DECISIONS.md` (решённое не пересматривать без причины).
4. Есть новая версия от пользователя (`Pod: incoming/repo/` или GitHub) — сначала синхронизируй рабочую копию `Pod: lunnyi_ulov/`.
5. Есть файлы в `Pod: incoming/art/` — обработай их по арт-конвейеру.

## 2. Жёсткие правила кода
- **Godot 4.7**, рендерер **Compatibility**, экспорт **Web без потоков**. GDScript со статической типизацией.
- **Композиция, а не наследование.** Поведение — узлы-компоненты с `class_name`, одна ответственность, настройка через `@export`. Наследоваться только от встроенных типов Godot. Данные — в `Resource` (`.tres`).
- **Всё — сценами и узлами.** Запрещено `Node.new()`, сборка деревьев узлов в коде, рисование объектов через `_draw()`. Разрешено: `preload(...).instantiate()` готовых сцен, изменение свойств, твины.
- Сигналы вверх, вызовы вниз; события между фичами — `EventBus`.
- Никаких магических чисел — `@export` или Resource. Ноль ошибок и предупреждений.
- Имена файлов: латиница, `snake_case`, без пробелов.

## 3. Графика (PLAN.md §2.5)
- Любой новый графический элемент: временный вариант (генерация + доводка `tools/art/`) → сразу под финальным путём в `res://art/` → промпт ChatGPT в `docs/ART_PROMPTS.md` → показать пользователю.
- Финал из `incoming/art/` обрабатывается тем же скриптом и заменяет файл по тому же пути, без правки сцен.

## 4. Шейдеры (PLAN.md §2.6) — важное правило
- **Сначала картинка, потом код.** Перед визуальным шейдером сгенерируй 1–3 кадра «как это будет выглядеть в игре», положи в `docs/shader_refs/<shader_id>/`, покажи пользователю. Шейдер пиши по этим кадрам.
- Основа с godotshaders.com — только CC0/MIT; Shadertoy — только как вдохновение (по умолчанию CC BY-NC-SA); GPL — нельзя. Источник и кадры — в шапке `.gdshader` и в `docs/ASSETS_LICENSES.md`.

## 5. Тексты (PLAN.md §2.7)
- Русские тексты в игре — через правила humanizer-ru, английские — через humanizer (`docs/text/vendor/`). Голоса и запреты — `docs/TEXT_GUIDE.md`. Отметка — `docs/text/TEXT_LOG.md`.

## 6. Музыка и звуки (PLAN.md §2.8)
- Пишет агент: синтез на Python в `tools/audio/` → OGG. Бесшовные петли со слоями. Никаких сэмплов чужих треков.

## 7. Качество и контент
- Каждая фича проходит чек-лист «fancy & juicy» (PLAN.md §3) и требования Яндекс Игр (PLAN.md §4).
- Без крови, чёрной магии, религиозной символики, политики. Подходит для всех возрастов.
- Референсы пользователя (`Pod: references/`) — никогда в игру, промо или репозиторий.

## 8. Протокол сохранения (обязательно)
Чекпоинт — после каждого подэтапа и внутри крупного подэтапа каждые ~3–5 изменённых файлов:
1. Записать файлы в рабочую копию `Pod: lunnyi_ulov/`.
2. Обновить `docs/PROGRESS.md` (статус, «Текущее состояние», конкретный «Следующий шаг»).
3. Дописать запись в `docs/DEVLOG.md` по шаблону, с сообщением коммита и списком удалённых файлов (если есть).
4. Пересобрать архив: `python3 /files/pod/lunnyi_ulov/tools/make_archive.py v0.<этап>.<подэтап>` (без аргумента — только `latest`).
5. Сообщить пользователю: что сделано, как проверить (1–2 минуты), какой архив скачать, сообщение коммита.

## 9. Ограничения среды
- В Computer нет Godot и интернета: `.tscn/.tres/.gd/.gdshader` пишутся текстом; к каждому подэтапу — инструкция проверки.
- `.import` и `uid` создаёт редактор при первом открытии — их коммитит пользователь (см. `docs/GITHUB.md`).
